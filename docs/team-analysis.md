# 组队分析与区域赛推演

2026-10-13 · `team-tags-v1`。入口 `/team-analysis`，首页和区域赛进度均有链接。后端仅使用本地 SQLite 与随代码发布的目录，不在请求中抓外站，不读取其他工程运行数据库。

## 操作与数据口径

选择训练墙三位不同成员、来源和目标题目评级。选择一场历史区域赛及 30–600 分钟限时，点击「分析队伍」。结果包含综合 12 维雷达、最多 12 个自选原始 tag 的雷达、个人曲线、逐 tag 评级与首过前错误 / WA / 练习量 / 过题评级分布、重试条形图和比赛逐题推演。目标评级用于覆盖判定及练习建议，不参与能力估计本身。

个人训练只取活跃绑定，排除 `cpc_handle_kinds` 标记的团队账号、QOJ `ucup-team` 和 CF `author.members` 多人提交。多个个人账号同题去重，区域赛通过规范 ID 合并 Gym/QOJ/VJudge/洛谷 CF 别名；重复 AC 不增加题量，只更新最后 AC 时间。三位成员共享同一平台个人账号时拒绝分析，避免把一个人的历史重复算成双人覆盖。未标明的团队账号需先在区域赛页确认类型。

Codeforces 来源使用本地提交保存的官方问题 rating / tags。全部可比数据额外允许已映射区域赛的其他平台提交，采用 CF Bot 的 CF 风格经验评级。AtCoder 难度、洛谷分级和 LeetCode Easy/Medium/Hard 不直接换算成 CF 分数。缺 rating / tags 不猜测；无评级但有 tags 的题仍计练习量，不进入评级样本。缺样本标「证据不足」，不能解释成能力为零。

## 能力估计

对每个 tag / 综合维度，按题汇总首次 AC、最后 AC、首次 AC 前的错误。CE、待判、系统错误和活动日历排除。综合维度也按题去重；一道带多个标签的题分摊证据权重，防止一题被当作多份独立训练。

- 样本权重 `w = (0.8 + 0.2 exp(-距上次 AC 天数 / 365)) / max(1, 标签数)`。
- 有效题数 `N = sum(w)`，置信度 `c = 1 - exp(-N/8)`。
- 基础评级为 AC 题 rating 的加权 70% 分位数。
- 错误扣分 = `min(120, 加权平均 min(5, 首过前错误数) × 20 + 80 × 难度≤基础评级+200的未过题占比)`。高难挑战不会直接拖低较低档能力。
- 记忆扣分为加权平均 `100 × (1 - exp(-距上次 AC 天数 / 365))`，最多 100 分。
- 小样本扣分 `200 × (1-c)`，最终个人评级至少 800。至少 5 道评级 AC 且有效题数至少 3 才为可靠估计。

将可靠队员评级降序记为 A、B、C。双人通路为 `B + .15 min(400,A-B)`；C 也可靠时加 `.1 max(0,400-(B-C))`，最多 40 分备份奖励。A 至少有 8 道评级 AC 且置信度至少 .65 时可走专长通路 `A-250`。团队评级取可用通路最大值；没有通路时为空。至少两人达到目标为双人覆盖；专长通路达目标为单人专长并提醒备份。三人评级不会线性相加。

## 逐题概率与时间

推演使用当前阵容和当前训练，排除目标比赛全部题目；它回答「现在这支队伍面对这份题单会怎样」。若题目全部 tags 都有可靠团队估计，使用其中最弱的 tag；缺标签或某个标签证据不足时，明确回退到团队综合基线。

设队伍能力 A、题目难度 D、限时 H（分钟）：

1. 潜在通过倾向 `q = 1 / (1 + 10^((D-A)/400))`。
2. 解出条件下首过时间采用对数正态分布，中位数 `m = s × 2^((D-A)/500)`，对数标准差固定 .8。
3. 限时内通过倾向 `P = q × F(H)`，F 为时间分布 CDF。解出条件期望是截断到 H 的均值，时间区间是该条件分布 10%–90% 分位。
4. 包含失败风险的预算期望为 `P × 条件期望 + (1-P) × H`。不把未解出的时间填成 0，也不把条件期望当作保证解出所需时间。

时间观测使用 CF 正式 / VP 首次 AC 的 `relativeTimeSeconds`，范围为 0–6 小时；练习提交、已有 AC 后的重复参赛不作为新时间样本。它是开赛至首次 AC 的累计时间，含读题与排队，不等于纯编码时长。至少 8 个样本时，把每个样本按 `(D-A)` 归一化，用中位数设置 s；否则使用 45 分钟经验先验。历史分位数用于给时间基准增加扰动范围。当前版本未用区域赛测试结果拟合时间参数。

概率区间扰动能力 `±(150+350×(1-c))`，加入 CF Bot 发布难度区间的宽度，并扰动时间基准。它是模型敏感性范围，**不是已经校准的统计置信区间**。时间区间也是模型分位范围，需要通过回测检查覆盖率。逐题倾向之和作为近似预计题数，没有对一台机器、读题顺序、队内沟通和并行分工做赛程仿真，不能承诺整场解题数量。

## 认证历史回测

登录的正式成员被选入当前三人时，回测其已认证的历史参赛记录。为了延续区域赛页的本人读取范围，匿名和未选入的账号不能读取别人的认证历史。当前认证快照必须在 24 小时有效期内；按最新 claim 状态与稳定 UUID / redirects 解析，撤销和歧义关联不归属。

每场还原当年真实三人名单，不用现在挑的三人冒充历史队伍。三位队员必须全部已认证且关联 Wall 个人记录，缺队友、赛前样本、目录或完整现场证据时列出跳过原因。赛前截断采用 DLUT 比赛日期在 UTC+8 的零点，严格早于此时，并排除目标比赛所有别名题目。比赛中及赛后补题不会反流到能力和时间参数。用原榜单时长进行回测，不用推演页的可调限时篡改历史赛制。

同题只计一次队伍结果，现场 AC 不写入个人提交。XCPCIO 从已审计的 `accepted_runs` 取最早 AC 时间；RankLand 从 `source_statuses` 的 AC/FB 时间及原始单位取值。人工导入只有通过标记时仅参与概率回测，不补造时间；未通过题不是时间 0。

输出包括逐场/逐题预测与实际、概率分桶、相近队伍战力 / 题目评级分桶的历史通过率与平均首过时间、Brier、tag 模型与同题综合基线的 Brier、解出题时间 MAE 和模型 10%–90% 时间区间覆盖率。时间指标只针对有可靠时间的 AC，未过题保留在概率指标中，不能将条件时间指标解读为包含失败的整体误差；另列未过按比赛时长截尾的预算期望 MAE。

CF Bot 逐题评级诊断比较实际通过率与预测通过率。至少 5 支不同历史队伍且均为正式成绩才提示偏高 / 偏低（残差绝对值 > .25），否则显示样本不足。本人通常同场只有一次参赛，首版更可能提供证据及残差，而不是足够的改分结论。评级来自同场榜单统计，本身可能包含被测队伍；这是回顾性诊断，无法宣称独立验证。不会自动改 CF Bot 分数或调参后再用同一场证明有效。

## 目录与标签补充

`catalog/regional_ratings.json` 复制自 CF Bot 的发布快照，包含 65 场 / 832 题、10 场未评级原因、统计基准、模型辅助、范围和证据 SHA-256。方法 `standings-medal-v1`，固定 board-data revision `7d626ddad0b98e8f79ddca7072421cee0a9f00e8`，为经验刻度，非官方 CF Rating。后续版本需同步完整经过核验的发布文件，不能写运行库评级冒充发布结果。

该评级快照没有 tags。可使用已同步的 CF tags，并在 `catalog/regional_tags.json` 按规范题目 ID 补充经题解核对的标签，附可追溯来源：

```json
{"version":1,"problems":{"规范题目ID":{"tags":["dp","trees"],"source":"官方题解链接"}}}
```

示例不代表任何具体题目的标签。空目录表示尚未人工核对。没有标签时预测及回测使用综合能力，页面显示缺失和回退口径，不能说 tag 雷达已经由这场验证。
